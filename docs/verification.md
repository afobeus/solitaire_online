# Проверка реализации

Дата: 3 сентября 2026 года. Windows, Node.js 24.19, встроенный Chromium; Linux-контейнер Node 24 и Caddy 2.10 через Docker Desktop. Автоматический набор тестов и CI в поставку не включены. Для проверки использовались реальные HTTP/WebSocket-клиенты и отдельные временные базы, а граничные состояния проверялись прямыми вызовами серверных модулей.

## Проверено через реальный сервер и два независимых WebSocket-клиента

- Регистрация двух пользователей, выдача сессий, вход после перезапуска.
- Создание комнаты, присоединение, готовность и один общий матч.
- Перемещение, подбор щитов и «Подсмотреть», серверная фильтрация позиций вне видимости.
- Единственная общая дуэль при столкновении. Одинаковые начальные поля у участников.
- Сервер запрещает действия до старта и некорректные карточные команды.
- Добор немедленно обновляет представление соперника; обычные изменения приходят патчами с последовательными номерами.
- Закрытые столбцы и колода представлены количествами. В обычных снимках нет значений закрытых карт, seed или порядка колоды.
- «Подсмотреть» раскрывает три ближайшие карты только владельцу, затем раскрытие удаляется.
- Победа по очкам, расход щита проигравшего, возвращение на безопасные клетки.
- Краткий обрыв восстанавливает состояние; новая вкладка явно отбирает управление.
- Одновременный уход обоих участников завершает матч без победителя.
- Зона сужается, оставшийся снаружи выбывает, победитель определяется сервером.
- Финальные пары, ничья, дополнительный расклад и явное сообщение о жеребьёвке.
- Долгое отключение приводит к победе оставшегося соперника.
- После перезапуска сохраняются аккаунты и агрегированная статистика; четыре завершённых матча дали ровно четыре записи матчей и восемь результатов.

Для ожиданий использовались ускоренные параметры отдельных проверочных запусков. Настройки продукта по умолчанию сохранены: 3 секунды отсчёта, 180 секунд боя, 30 секунд дополнительного раунда, 20 секунд переподключения.

## Проверено в графическом интерфейсе

- Регистрация, лобби, создание комнаты, два участника в комнате, готовность и запуск.
- Карта, видимые предметы, щит в инвентаре, перемещение стрелками при фокусе на кнопке.
- При ширине 1366 пикселей соперник слева, собственное поле справа; оба расклада видны одновременно.
- Туз перенесён в основание выбором и кликом по цели; допустимая цель подсвечена.
- Дама перетащена на короля; после хода открылась следующая закрытая карта.
- Недопустимый ход получил русское сообщение об ошибке.
- Добор второго реального клиента показан в левом поле (24 → 23 карты).
- Профиль и русские состояния пустого лобби, подключения и ошибок.
- Регистрация и авторизованное лобби работают также в режиме Vite.

## Проверено прямыми вызовами правил и жизненного цикла

- Финал с 8 участниками завершается за 7 решающих дуэлей; очередь с 7 участниками тоже завершается.
- 52-я карта в основании немедленно заканчивает бой; повторные обновления не дублируют результат в SQLite.
- Пустая колода соперника сохраняет предмет «Подсмотреть».
- Разведка временно раскрывает далёкую позицию; после срока скрывает её снова.
- Нельзя подобрать второй щит или четвёртый предмет; лут остаётся на карте.
- Повторный проход колоды сохраняет порядок; функции правил не мутируют исходное поле.
- Передача владения комнатой при выходе владельца, запрет входа в заполненную комнату и удаление пустой комнаты.
- Раскрытие фиксирует максимум три карты на момент применения; новые доборы соперника не раскрывают дополнительные карты за то же применение.
- Таймер дуэли переходит в дополнительный раунд даже при двух отключённых участниках. После истечения обоих сроков переподключения матч заканчивается без победителя.

## Сборка и размещение

- `pnpm typecheck` и `pnpm build` проходят.
- Linux Docker-образ действительно собран из Dockerfile с lock-файлом.
- Compose поднял приложение, постоянный том SQLite и Caddy; healthcheck стал healthy.
- HTTPS проверен клиентом, доверяющим выданному локальному CA Caddy, без отключения проверки сертификата.
- Через HTTPS проверены регистрация, cookie Secure/HttpOnly/SameSite=Strict и соединение WSS.
- Production HTML отдаётся с CSP; API здоровья проверяет SQLite.
- Фактически выполнены `deploy.sh`, `backup.sh`, `restore.sh` и `update.sh`.
- Backup прошёл `integrity_check`; restore остановил приложение, сохранил прежнюю базу и запустил приложение снова. Аккаунт сохранился после восстановления.

## Что не проверялось

- Размещение на внешнем VPS и сертификат Let's Encrypt для публичного домена: домен и сервер не предоставлены.
- Производительность под нагрузкой на 1 vCPU / 1 ГБ RAM. Пределы конфигурации не являются гарантией пропускной способности.
- Полная партия до 52 карт, сыгранная человеком через браузер; этот граничный переход проверен на контролируемом серверном поле.
- Матч с восемью одновременно открытыми графическими браузерами: проверен серверный цикл 8 участников и сетевой цикл двух реальных клиентов.
- Полноценная мобильная эргономика и кроссбраузерная матрица Safari/Firefox.
- Отдельный дополнительный вызов `pnpm start` был отклонён автоматической проверкой инструмента (`blocked by policy`, без уточнения причины). Эквивалентная команда `node dist/server/index.js` фактически запускалась; production-образ с той же точкой входа собран и проверен через Compose.
